# **2. Docker — Introduction**

Docker is a containerization platform that packages an application and its dependencies into an isolated environment called a container. It helps applications run consistently across environments.

- **Image:** Template used to create a container.
- **Container:** An instance of an image.
- **Dockerfile:** Instructions used to build an image.
- **Network:** Enables communication between containers.
- **Volume:** Keeps data persistent beyond a container's lifecycle

# **3. Dockerize**

Containerized the Express backend without Docker Compose or a YAML file. Ran PostgreSQL in a separate container and connected both containers using a custom bridge network and persistent volume.

**Dockerfile**

```dockerfile
FROM node:alpine
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
EXPOSE 3000
CMD ["npm", "start"]
```

**Commands used**

```bash
docker --version
docker pull postgres
docker build -t resource-library .
docker network create resource-library-net
docker volume create resource-library-data
docker images
docker ps
docker ps -a
docker network ls
docker network inspect resource-library-net
docker volume ls
docker volume inspect resource-library-data
docker logs <container>
docker exec -it <container> sh
```

The PostgreSQL data volume was mounted at `/var/lib/postgresql/data`. The application was tested at `http://localhost:3000`.

# **5. Nmap**

Used Nmap to scan authorized lab hosts and explore active hosts, open ports, and running services.

**Commands to perform the scans**

```bash
nmap <target-ip>
nmap -sn <network-range>
nmap -sV <target-ip>
nmap -O <target-ip>
nmap -p <port-list> <target-ip>
```

- `-sn` discovers hosts without a port scan.
- `-sV` probes services to identify versions.
- `-O` attempts operating-system detection.
- `-p` specifies the ports to scan.

Only scan systems you own or have permission to test.

# **8. SSH: Key Discovery and Transfer**

Used two Ubuntu EC2 instances to practise SSH access and SCP transfer. Test files were archived, encrypted, transferred, decrypted, and extracted. SHA-256 checksums were compared to verify file integrity.

**Example commands used in the workflow**

```bash
ssh-keygen -t ed25519 -f lab_key
ssh -i <transfer-key.pem> <user>@<server-b-ip>
scp -i <transfer-key.pem> <file> <user>@<server-b-ip>:<destination>
sha256sum lab_key lab_key.pub
```

The Bash workflow used `tar` to archive files and OpenSSL with AES-256-CBC and PBKDF2 to encrypt/decrypt the archive. The checksum values matched on both servers. Both EC2 instances were terminated after the practical.
